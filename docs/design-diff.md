# Native source-bound design diff (local Java profile)

**WIP checkpoint:** implementation is preserved for review; only the missing-API RED was run. The implementation and tests below have not received a GREEN build or independent acceptance. Task3.5 remains incomplete.

`SourceIndex::from_java` consumes only the private result of the pinned Java provider. It freezes the language model version, provider/configuration identity, actual bytecode source digest, raw capture digest, classfile hashes, symbols, static edges and unresolved/native gaps. There is no external CodeGraph/SCIP parser, plugin dependency or deserializable index qualification. The canonical serialized index has a content digest and `artifact://archguard/source-index/<digest>` reference.

The local diff profile requires an externally approved ArchitectureBaseline whose source reference equals that actual index URI and whose immutable binding source digest equals the native source digest. `compare` freshly calls the existing external authority port with the original protected approval policy and protected current time. A digest match alone is never approval. Other baseline consumers retain their existing source-reference semantics. This profile does not supply a production identity provider or latest-baseline registry.

The controller separately supplies expected identities for both indexes and requirement/obligation mappings. Stale model/source/capture/configuration identities fail and require reindexing. The candidate identities and mapping are frozen into the diff policy digest; they do not alter or expand the approved baseline contract. Mapping references must name obligations in that approved baseline. They are trace inputs, not proof that tests executed or that a second requirement received approval.

The report compares complete structured symbol identities and retains added/removed declarations and changes in native capture position. Method signatures participate in identity. Renames, signature changes and owner changes without a verified stable mapping remain removed/added records; matching names do not prove continuity. Different provider configurations add an ownership-attribution gap. Capture positions are TSV record locations, **not Java source line positions**. Changed classfile keys are reported from actual byte digests; they do not assign body changes to particular methods. Classfile hashes identify actual compiled input; no source-to-bytecode reproducibility claim is added.

Public visibility, method-body semantic equivalence, complete dynamic Calls consumers and consumers outside the frozen native scope are explicitly unknown. Existing native unresolved relations and parse gaps remain in the referenced indexes. Even an empty declaration diff is not zero-impact or compatibility evidence. Static consumer inventories retain actual DependsOn edges from both snapshots; they are not a synthesized call graph or a claim that every listed consumer changed. Shared requirement symbols retain each requirement and obligation set; different files do not establish compatibility. No GE grant or test completion is produced.

Input admission uses borrowed serialization before ownership/hash (1MiB encoded metadata/index cap), native observation budgets and at most64 requirement mappings. Diff rows borrow immutable index/input storage, and expanded output is counted before serialization ownership. Canonical raw index bytes, identities and output can be retained by a controller; access authorization/publication and immutable history are separate existing boundaries.

`tests/design_diff.rs` compiles real JDK21 classes and executes the pinned Java provider. It exercises renaming, static consumers, cross-requirement sharing, module reassignment, unchanged declarations with unknown impact, stale indexes, fresh revocation/expiry and oversized metadata. This is a partial source-bound diff slice: original task3.5 remains unaccepted while visibility/body/call coverage is absent.
