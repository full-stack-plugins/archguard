# ADR 0005: Explicit fixture-profile SpecGuard references

Status: implemented locally, pending independent review. Scope: SG architecture handoff consumption for AG task 3.4 interoperability, not architecture baseline lifecycle or production authentication.

The opt-in `ProtectedTraceMapping` freezes externally owned SG expected artifact/repository/candidate/base/source/baseline/scope/profile pins and explicit requirement/ADR → GG requirement alias → existing Cargo rule IDs. It requires exact mapped requirement, ADR pair and rule coverage, unique pairs and unambiguous aliases. Canonically sorted links and complete protected Cargo profile participate in its digest. SG text cannot create rules, modify severity or authorize exceptions.

`ArchitectureTrace::read` calls the actual strict SG decoder, which rescans its frozen snapshot and derives references again. AG independently validates the actual GG candidate and reads every SG snapshot path from GG's verified private commit objects. Dirty or unrelated bytes are rejected even when SG itself correctly describes a dirty snapshot. Git equality applies to declared SG source scope; it is not a claim to discover every repository document.

The only accepted SG authentication profile is fixture-only. The caller supplies the existing SG approval validation port and clock; expiry, revocation, unavailable authentication and scope mismatches reject consumption. This is not a production identity provider. The fixture baseline is copied byte-for-byte from SpecGuard's approved-baseline fixture at ee8fa5c7b3cb9a4a454d5d08385194ee5e938c80. Its historical placeholder source revision is not proven to exist in Git. Its baseline, requirement and obligation identities remain identical to the shared SG/TG fixture.

`baseline_obligations` comes from SG's real exporter over the frozen approved baseline graph. Its candidate/source fields describe that historical baseline, not candidate test coverage. No completeness field is rewritten and no TestGuard execution is claimed. The typed candidate trace currently has no dedicated candidate-obligation exporter; the API name preserves this distinction. GE `binding.baseline_digest` stays absent because these fixture references are not an authenticated approved architecture baseline. Envelope approval references stay empty.

`TracedCargoEvidence` freezes the entire owned trace receipt as an inventory identity before preparing actual Cargo evidence. The new `archguard.spec-trace-evidence/v1alpha1` wrapper carries the full baseline, explicit mapping, source references and baseline obligations around the existing Git evidence bundle. Independent load requires raw SG bytes, the protected mapping, actual repository/candidate, current fixture port and clock. It checks exact receipt equality, actual Git evidence and the unique SG inventory identity, including after artifacts are rehashed. Strict nested deserialization retains duplicate/unknown-field rejection. Cancelled/error native evidence retains a null decision and bound trace. Source digests remain separately scoped SG snapshot, GG candidate and AG measured inventory values.

Budgets: at most 256 requirement scopes/links/rules per link; identity strings 256 bytes and aggregate mapping identity bytes 256 KiB; repository pin 4096 bytes, digests 71 bytes, OIDs 64 bytes before serialization; protected context 1 MiB; SG raw handoff 1 MiB through SG's reviewed bounded parser; trace receipt 2 MiB; final traced bundle 16 MiB. Existing GG source and Cargo/GE analysis budgets remain effective.

The basic Cargo producer and legacy CLI remain independently usable when SG validation is unavailable. This path adds no provider, signing, remote writes, publication CAS, general language extraction or production enforcement. The local path dependency is a development integration, not an independently released compatibility claim.

Reproduce the actual writer/reader fixture with `cargo run --locked --offline --example export_spec_trace -- NEW_DIRECTORY`. It commits Cargo and explicit Markdown inputs in a temporary Git repository, uses real SG discover/freeze/export, validates committed bytes and executes actual Cargo/GE. It emits source.bundle, raw handoff, external fixture context, strict traced/Git/native bundles and baseline obligations. The example's fixture approval port is explicitly test-only.
