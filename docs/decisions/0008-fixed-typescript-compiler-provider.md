# ADR0008 — fixed TypeScript compiler API and closed input host

Status: implemented for independent task2.3 review; no production authority claim.

Use the already installed official TypeScript5.9.3 compiler API on Node24.19.0. The existing evaluation demonstrated real alias resolution and overloads. A custom source parser would duplicate semantics; invoking tsc JSON diagnostics alone would not establish declaration identities. The selected adapter therefore uses createProgram/getTypeChecker/getAliasedSymbol and real declaration positions, through a closed CompilerHost. Official references: [Compiler API](https://github.com/microsoft/TypeScript/wiki/Using-the-Compiler-API), [project references](https://www.typescriptlang.org/docs/handbook/project-references.html), [module configuration](https://www.typescriptlang.org/tsconfig/).

`fixtures/languages/typescript/tool-profile.json` fixes actual Node executable SHA256, compiler JS and every allowed standard-library declaration file SHA256. The Node executable is bounded-copied into the private tool directory and its copied bytes are verified before execution; replacing the original path cannot change a prepared toolchain. The compiler license is Apache2.0, with exact installed LICENSE.txt hash in that profile; existing package-lock records registry integrity. Node's actual distribution is separately installed, not vendored by this slice. The inspected runtime root has no top-level license notice and its --license option is unsupported; LICENSE-PROVENANCE.json records that limitation. The [official Node project license](https://github.com/nodejs/node/blob/main/LICENSE) provides MIT and bundled-component notices, but is not claimed to attest this exact installed binary's provenance. Its version/binary is frozen for compatibility, not authenticated identity. The helper source digest, tool profile and controller profile contribute to provider identity. No new dependency installation or download.

Rust freezes required .ts/.d.ts path→logical-module mappings and explicit paths aliases. Options are fixed ES2022/ESNext/Bundler/strict/noEmit, with explicit types=[], allowJs=false and no JSON module resolution. Project references are **Reject**: controller JSON rejects references and all unknown fields/options, and copied candidate tsconfig*.json is rejected. Candidate config never changes plugins/options or loads other files. Cross-package source types work only through required controller-owned source paths. No project-reference build, package.json discovery, node_modules resolution, code emission or candidate execution.

The native helper receives only captured required source text. CompilerHost readFile/fileExists/getSourceFile/directoryExists operate on that map plus exact copied standard libraries; they never fall back to ts.sys or real filesystem. Missing imports or scope produce compiler diagnostics and Unknown, not zero-edge success. The trusted compiler itself is required from its private copied tool directory; the candidate is never executable module input.

Relations are static file/module declaration dependencies backed by actual compiler-resolved import/export/type-reference, constructor and type-query declarations. Registered Type/Method symbols retain top-level type names and canonical compiler signatures; supported overloads retain distinct signatures. Source positions are actual TypeScript UTF-16 one-based line/columns with exclusive end. Missing-module scope placeholders and file-level diagnostic anchors are explicitly coverage bookkeeping, not observed declarations. Local/nested type/callable identities, import-equals/import-type syntax and unresolved references conservatively mark partial. No cross-language inference. Standard-library references are outside managed modules. Calls is always incomplete; confirmed static literal import targets do not establish runtime dispatch.

Input copying inherits the reviewed fixed-tool runner boundary. Limits:64 required sources,512KiB/file,4MiB copied input,256 copied entries,depth32,8MiB encoded request,65536 candidate AST nodes,4096 output records,8192 characters/record,1MiB combined subprocess output,20 seconds/invocation and256MiB V8 old-space limit. This is not an OS memory/process-count sandbox. Compiler parse allocations remain bounded by source bytes, heap and time before later AST/record checks. Diagnostics capped256. Native errors, timeouts, malformed data and budget failures are errors, not partial success.

The source digest covers exact required source bytes/missing inventory, protected profile and tool/helper identity. It is neither a Git candidate proof nor the Cargo inventory digest. Existing reviewed system rules/GE operate on these observations; no language-specific policy enters GE. No TypeScript evidence envelope or production authentication is added. Linux x86_64 and exact installed tools are the exercised profile.
