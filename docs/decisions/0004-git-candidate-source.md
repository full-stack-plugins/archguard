# Decision 0004 — local candidate object source binding

Status: implemented for independent review; tasks 4.2/4.4 remain unchecked. Uses additive GitGuard reader c33b28ac68c1a2db4b2fc87ff0c9dfcc33a3405f after runner52f07b serial handoff. This profile validates local immutable Git objects; it does not authenticate repository ownership, queue/controller identities, producer identity or approval.

GitCargoEvidence::prepare consumes a real GitGuard Repository plus CandidateSnapshot and owned ProtectedCargoPolicy. Snapshot validation checks repository/object format, actual candidate/base/member commits, actual candidate source digest and snapshot metadata. The caller-assigned repository label remains local. The exact protected AG profile digest must equal the GG policy digest. No root path or separate caller OID can choose different analyzed bytes.

The reader consumes only the repository's already isolated object store. Regular committed blobs are materialized into a new private directory. AG rejects unsupported paths (non-UTF8, target components and nonportable colon/backslash paths), symlinks/gitlinks and unsupported Cargo configuration/path escapes rather than silently dropping input. The file-only inventory of the isolated Cargo copy must exactly equal the candidate's file inventory before GE binding. Analysis still uses the existing Cargo declaration profile and fixed bounded tools; this is not a source language graph or active-build claim. A Git tree with unsupported files is a preparation diagnostic, not complete empty evidence.

The entire GG snapshot, including task, requirements, base, candidate, queue ID, members, allowed paths and GG source digest, plus actual object format are frozen into analysis inventory. A second key retains the exact file inventory digest. GE source_snapshot_digest remains the enhanced AG inventory digest including policy/tool/environment identities; it is deliberately different from GG's tree digest. No fresh worktree/index bytes enter the analysis after candidate extraction. GG snapshot validation may conservatively fail when its declared clean state no longer matches the observed worktree; this is not a freshness service or queue attestation.

The existing CargoEvidence::prepare(root, CandidateContext) and archguard.evidence/v1alpha1 format remain explicitly controller-resolved-unverified/advisory. They do not become verified from OID syntax. The separate archguard.git-cargo-evidence/v1alpha1 wrapper carries the unchanged inner Cargo bundle, exact GG snapshot, object format and file digest. Its bounded strict loader requires an independently supplied expected CandidateSnapshot and actual Repository; it compares every snapshot binding field, recomputes actual file digest, validates the native evidence and checks frozen Git inventory keys. Consumers requesting Git verification must use that entrypoint, not deserialize and trust self-asserted metadata.

Wrapper verification proves local consistency against expected objects, not producer authenticity or reexecution of Cargo. The caller must still use reviewed GE trust ports for production eligibility; an attacker can create self-consistent unsigned claims, and hashes are not authentication. Source inventory includes measured ambient configuration digests, not environment values. No baseline/approval grant, CAS admission, remote/ref write, checkout or hook execution is added.

Actual dependency on GitGuard requires Rust1.90; AG raises its declared minimum from1.85 for this concrete dependency. AG serde/tempfile align to GG's exact1.0.228/3.23.0 pins. Sibling development source is not an independent published release. Legacy regression and the full 74-test suite passed on both official Rust1.90 and default1.99. Raising MSRV enabled two existing collapsible-if lints; equivalent let-chain syntax was applied without changing native behavior.

Independent review correction: Git wrapper verification compares the complete declared `file:` key sequence with the actual candidate file inventory, not just its separate digest. The entire reserved `identity:gitguard` namespace must contain exactly the current binding and file identity keys. Removing a real file, inserting a foreign file or adding a conflicting/unknown Git identity is rejected even after recomputing the domain artifact digest. These checks reject observable source contradictions; they do not convert unsigned evidence into authenticated producer claims.
