# ADR0007 — fixed installed JDK classfile provider

Status: implemented for independent2.1/2.2 local profile review. Existing typed model and system-rule semantics are retained.

Choose installed Debian OpenJDK21.0.12.1's `jdk.jdeps/com.sun.tools.classfile.ClassFile` and `Dependencies.getClassDependencyFinder`, with explicit --add-exports. The native parser and dependency finder produce actual observations; Rust does not claim qualification of a hand-written JVM parser. javap verbose output is retained only as an independent native inspection fixture, not parsed as a stable schema. No ArchUnit download/dependency was added. Native API availability, actual overloaded descriptors, reflection and invokedynamic were exercised before implementation in ledger/archguard-java-evaluation.

The profile fixes version and exact installation hashes from fixtures/languages/java/jdk-profile.json. It hashes release,java,javac,lib/modules and lib/server/libjvm.so, with a192MiB/file and20second identity-reading ceiling. Runtime-tested host is Linux x86_64. Internal API changes, another build or unknown hashes reject instead of silently widening compatibility. The private helper is compiled from committed Apache-2.0 source, with annotation processing disabled and bounded JVM flags. Actual compiled helper bytes participate in identity; build log records exact invocation/version/success and output. No candidate class appears on the execution classpath or is loaded.

Official [OpenJDK dependency finder source](https://raw.githubusercontent.com/openjdk/jdk21u/master/src/jdk.jdeps/share/classes/com/sun/tools/classfile/Dependencies.java) confirms the finder scans class references and declared signatures. It does not establish runtime dispatch. The selected exact local binary, rather than that moving source branch, controls compatibility. [javap documentation](https://docs.oracle.com/en/java/javase/21/docs/specs/man/javap.html) describes the verbose/descriptor/disassembly output used for cross-checks.

Installed license record: `/workspace/guard-toolchain/jdk21/usr/share/doc/openjdk-21-jre-headless/copyright`, general Files:* stanza `GPL2 with Classpath exception`, source OpenJDK jdk21u; other bundled components have their listed notices. See [OpenJDK license](https://openjdk.org/legal/gplv2%2Bce.html). We invoke the installed distribution; no JDK implementation source or binary is vendored into ArchGuard. fixtures/languages/java/LICENSE-PROVENANCE.json identifies the exact installed notice hash. This records the actual dependency license; it is not a production redistribution decision.

Protected required type→logical-module and explicit external-type mappings are immutable. Java platform types under java/ are fixed excluded external scope unless required explicitly. Only selected classfiles65.0 are claimed; missing classes and unknown/preview versions remain gaps. Class header/internal name/path/parsed length must agree. Opaque unsupported attributes, reflection, native implementations and dynamic type targets are unknown; static type edges never imply complete Calls or runtime coverage. A path is an actual native capture record with class/offset attribution, not an inferred Java source line. Source digest covers exact selected input bytes/missing markers and frozen profile/tool/helper identity.

Budgets and full capability matrix are in analyzer-capabilities.md. Existing system rules consume the actual LanguageObservation; legal/forbidden/missing fixtures run through real GE. No new policy evaluator, authenticated producer, Java evidence envelope, classpath builder, JAR expander or source-language compiler service is claimed.
