# Local approved domain declarations and static type access

Task3.2 is a **partial** implementation. Context/Aggregate/Invariant/Transition declarations and test-obligation mapping are available, together with actual Java static dependency evaluation. Complete method-call/state-transition semantics remain unsupported; this slice does not lower the original requirement or enable task3.3 method side-effect contracts.

`DomainContract::freeze` accepts explicit stable SymbolIds, context ownership, aggregate entry/internal-state types, invariants, transition method/state declarations and a frozen actual provider profile. It does not infer responsibilities from AppService/Aggregate class names or similar method names. Input admission occurs before hashing/cloning:1MiB encoded domain metadata,64contexts,128aggregates/invariants/transitions,256members/context and256-byte declaration IDs. Declarations sort by ID before computing the specification digest. HeuristicStateAccess cannot use Enforce.

The full domain specification digest appears in every generated exact GE assertion and contract revision. A candidate cannot replace domain semantics while retaining the approved contract. Each evaluation requires a freshly externally qualified immutable Approved ArchitectureBaseline with exactly this contract digest and full generated obligation set. Revoked, expired, unavailable, mismatched or merely self-marked baselines cannot evaluate. Qualification uses the existing GE provider; neither this module nor source ADR text issues approvals. Trusted time and protected policy/provider selection remain controller responsibilities.

`evaluate_java` takes only the actual native `JavaAnalysis`, not caller-created LanguageObservation claims. Its immutable native provider identity must equal the frozen profile. All declared symbols must exist and static dependency coverage must be complete to claim complete facts. Missing required classes/symbols and native extraction gaps produce partial evidence; GE partial coverage remains BLOCK regardless of review/advisory severities.

StaticStateAccess has one narrow, deterministic meaning: no observed type other than the declared aggregate entry type or internal-state type may directly depend on the declared internal-state type. An AppService referencing Aggregate while Aggregate references State is legal for this static rule; an AppService directly referencing State is a locatable static violation. This does **not** establish which method executes, whether a field is mutated, or whether a runtime invariant holds. Source evidence is real captured Java type references with capture locations; caller must retain the native capture/classfile source independently. The evaluation includes actual source and raw capture digests.

Transitions record explicit from/to state and canonical method identity for test obligations. A TransitionEntry invariant always has an unsupported semantic coverage gap with current extractors: Java/TypeScript do not provide complete Calls/state behavior. No observer override fills that gap. A contract containing only static checks may be complete for this static profile while its separately exported transition test obligations remain unexecuted. HeuristicStateAccess uses the same observed reference evidence as a review/advisory suggestion, never confidence-based enforcement.

The serialized `archguard.domain-evaluation/v1alpha1` contains the actual GE contract/facts/report, finding witnesses and versioned local test-obligation references. Their identity derives from the frozen specification and declaration, and each output binds baseline/source digests. `TestExecution::NotRun` is mandatory; this is a controller input for future TestGuard consumption, not a TG test result, approval, executed coverage or end-to-end TG integration claim. No new engine envelope, actual Git candidate provenance, production issuer, Java CLI, or global source scope is supplied here.

Validation uses real fixed JDK21 javac/classfile extraction of legal AppService.cancelTask→Aggregate.cancel type references and direct State access, missing class coverage, unavailable transition semantics, fresh authority failure/revoke/expiry, altered protected severity, heuristic restriction, input budget and deterministic ordering. Actual Java methods are compiled but never executed by this test/extractor.
