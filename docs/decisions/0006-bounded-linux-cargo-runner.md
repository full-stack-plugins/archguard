# ADR0006 — bounded Linux fixed-tool runner

Status: implemented for independent task1.4 review. Supersedes ADR0001's process-group and source-copy implementation details; it does not turn the runner into a general hostile-native-tool sandbox.

The enhanced Cargo declaration profile supports little-endian Linux x86_64 and aarch64 with seccomp, waitid and procfs. Actual runtime validation here uses Linux x86_64. Other execution targets return UnsupportedPlatform; seccomp installation failure returns Start and does not fall back. Legacy CLI execution remains unchanged. Tool paths, arguments and environment are controller-owned; candidate Cargo configuration and paths escaping the copied root are rejected. Cargo metadata uses --offline --no-deps and never runs candidate build scripts or policy scripts. Trusted Cargo/rustc and system runtime files are outside the source allowlist, not candidate input grants.

Before spawn, all Budget values must be nonzero (depth may be zero) and no larger than the defaults:20seconds per invocation/copy, combined stdout+stderr8MiB,16MiB per file,128MiB copied bytes,10000entries, depth64. Callers can tighten but not enlarge these maxima. Output reads are nonblocking and round-robin so one stream cannot starve the deadline; only stdout is retained. Invalid budgets are Input, timeout is Timeout, output overflow is OutputLimit and nonzero tool termination remains Exit. Cleanup failures have their own Cleanup variant. These map to enhanced execution errors, not successful empty observations; actual valid coverage gaps retain Partial and legacy failure-to-partial behavior remains unchanged.

The child starts in a dedicated process group. A precomputed, allocation-free pre_exec hook sets no_new_privs and an inherited seccomp filter. It rejects setsid/setpgid, unshare/setns and clone namespace flags. clone3 is refused with ENOSYS so libc can use inspectable clone; ordinary process/thread creation stays available for Cargo/rustc. Unexpected syscall ABI/x32 is killed. The leader is observed through waitid WNOWAIT and remains unreaped until the entire group is signalled, preventing PID reuse between leader exit and group cleanup. After signalling, leader reaping is bounded to250milliseconds. This includes successful leaders with pipe-closing background descendants. It is not a resource container for arbitrary malicious native code, a process-count controller, or a guarantee to undo uninterruptible kernel I/O.

Source copy now pins directory descriptors. Canonical source must lie beneath a canonical allowed root. Each source path component and each enumerated child is opened with openat/O_NOFOLLOW; O_NONBLOCK and fstat prevent FIFO/special-file swaps from blocking or being accepted. Enumeration uses only internally generated /proc/self/fd/N paths; the fd remains authoritative if the directory name is replaced by a symlink. Only regular files/directories are copied. Hard links are copied as bytes, never preserved as links. Fresh tempfile directories provide atomic private0700 creation and RAII cleanup. Copy enforces deadlines, entry/depth limits and per-file/cumulative byte ceilings during bounded chunk reads, not just pre-copy metadata. Manifest/config validation occurs on the private copy. No candidate directory is re-opened by its pathname while recursively copying.

This profile constrains declared input traversal and trusted fixed-tool execution. It does not block all ambient file access by a deliberately malicious replacement executable, provide mount/network namespaces, or authenticate tool provenance. Actual environment probes: bubblewrap user namespace setup fails on read-only uid maps; Landlock ABI query returns ENOSYS. No unavailable sandbox is reported as active. The source and lifecycle controls above are independently executable without selecting a production identity provider.

Kernel references for the inherited filter/privilege semantics: [seccomp filter API](https://www.kernel.org/doc/html/v6.3/userspace-api/seccomp_filter.html) and [no_new_privs](https://docs.kernel.org/userspace-api/no_new_privs.html). This ADR's local capability results come from actual commands, not inferred kernel-version support.
