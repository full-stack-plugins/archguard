# Decision 0003 — deterministic local module graph rules

Status: implemented for independent task 2.5 review. This is a local in-memory evaluator over the existing LanguageObservation model. No Java, TypeScript or Rust semantic extractor is enabled. Provider profile and completeness declarations are inputs, not authentication or proof against repository files. SourceSpan witnesses preserve the actual supplied confirmed edges; the evaluator does not invent a target or source span. Production provider coverage, approved baseline authentication and candidate binding remain separate tasks.

ProtectedSystemPolicy::freeze owns exact language/provider identities, the complete required module set, and rules. Keys retain structured language/module identity. Every layer rule must assign every protected module; forbidden direction endpoints must be in that set. Rules have unique IDs and preserve enforce/review/advise. Provider languages must equal the protected module languages. The policy digest includes profile version, provider requirements, all modules and all rules, sorted canonically. Caller modifications after freezing cannot shrink these owned values. No field constitutes an approval grant.

The supported relation is DependsOn. Calls-based system policies return unsupported. All rules apply to the module graph induced by confirmed DependsOn edges. Higher layer numbers may depend on lower or equal numbers; lower-to-higher dependencies violate Layers. ForbiddenDirection matches exact ordered module keys. Acyclic detects module cycles, including explicitly observed Module-to-Module self dependencies. Edges between implementation symbols in the same module are internal and do not form a module dependency. Cross-language edges are not expressible by the current LanguageObservation model and are not a supported capability. Multiple languages may supply separate graphs; identical module names remain distinct.

Every required provider and module must be observed, and DependsOn coverage must be complete with no unresolved DependsOn relation. Missing providers/modules, unknown dependencies, incomplete declarations or extra unprotected observed modules produce partial facts. Wrong or duplicate provider profiles are explicit errors. Partial stays BLOCK/INDETERMINATE for every enforcement mode under current GE semantics, even if a real violation witness exists. This deliberately uses the native global completeness model; it does not claim per-rule partial evaluation capabilities.

Ordered iterative DFS produces the first real cycle witness. Every witness follows an actual module edge, retains original symbol identities and source spans, and closes at the module level. A module-level cycle need not be a same-symbol call cycle. A single witness suffices to establish failure; this is not an enumeration of every cycle. Stable symbol/edge/unknown ordering makes reports insensitive to observation insertion order. Disconnected graphs and explicit self cycles are covered. No recursion or enumeration of all simple cycles is used.

ArchGuard owns layer, direction and cycle semantics. For each finding, it emits an exact neutral forbid_relation tuple keyed by rule ID, system profile and complete protected policy digest. The source references the SHA256 of the full typed finding including its path. The read-only SystemEvaluation retains those findings alongside the native contract/facts/report. GE integration::evaluate_bounded performs the actual enforcement and report generation; no new engine assertion or approximate relation matcher is introduced. Native reports are unsigned and unchanged. The source snapshot digest covers canonical supplied symbols, all confirmed edges, unknown provenance, provider identities and effective coverage. This is a digest of local model inputs, not a Git tree or authenticated source inventory. Source/coverage digests are not reusable authorization.

Budgets apply before graph expansion: at most 3 observations, 1024 required/observed modules, 4096 symbols, 8192 raw edges, 4096 unknowns across providers, 64 rules, 256-byte policy identifiers/profiles/modules, 1 MiB counted policy text, and 4 MiB counted observation text. Raw duplicates count against input limits. Repeated layer maps are checked before canonical serialization. Finding expansion is limited to 8192 total witness steps and 4 MiB witness text; overflow returns an error rather than silently dropping findings. Canonical hashing uses the existing bounded 16 MiB serializer; engine report budgets remain shared. These limits apply to already-owned typed inputs; construction of arbitrary caller objects is outside this evaluator's control. The library does not spawn tools or allocate a separate build cache.

SystemEvaluation is an in-memory API, not the Cargo evidence bundle profile. Serialize support on model/finding types serves canonical hashing; no public decoder, unversioned wire promise, new CLI mode or authority envelope is published. Existing Cargo producer, native analyzer, legacy CLI/schema/exits and fixed golden files remain unchanged.
